A 1 kg box dropped onto a plane


The box starts with its centre at 0.30 m and its bottom face 0.25 m above the plane. It lands at $t = 0.228$ s (free fall predicts 0.226 s; the engine's 2 ms Euler step lands one step later) at about 2.2 m/s. MuJoCo's contact is soft: the constraint behaves like a critically damped spring with time constant 0.02 s (the default solref), so the box sinks 14.8 mm into the plane at impact and settles at 0.108 mm, where the spring force balances the weight. At rest the four corner contacts each carry 2.4525 N, and their sum is $mg = 9.81$ N. The strip chart samples the penetration after every engine step, which the 30 ms impact needs; a frame-rate sample would catch it at two or three points. The numbers come from Python mujoco==3.14.0 on the same XML; tools/twins/mujoco.json checks that this page's engine produces them.

Block on a tilted plane: creep and slip




Coulomb friction holds the block when $\tan\theta \le \mu$; with $\mu = 0.5$ the friction angle is $\arctan 0.5 = 26.57^\circ$. MuJoCo's friction is a soft constraint, so a held block still creeps. At $20^\circ$ the pyramidal cone creeps at 1.8 mm/s and the elliptic cone at 0.87 mm/s; noslip_iterations = 10 stops the elliptic creep (0.0001 mm/s) and leaves the pyramidal creep unchanged in 3.14.0. Above the friction angle the block slides with acceleration $g(\sin\theta - \mu\cos\theta)$: at $30^\circ$ that is 0.657 m/s$^2$, which predicts 328.6 mm in the first second; the engine gives 329.3 mm. Moving the $\mu$ slider changes the ramp's friction while the block moves, so lowering it past $\tan\theta$ starts the slide. Moving the tilt resets the block onto the rotated ramp. The run restarts every 2 s.

Tumbling box in orthographic 3D




The same model as the box drop, with a different initial state set in onReset: the box starts 0.25 m up, rotated 35 degrees about the axis (1, 1, 0), moving at 0.4 m/s along x and spinning at (6, -6, 2) rad/s. It lands on a corner, rocks through edge contacts (one or two contact points) and settles on a face (four). MJ.draw3 culls the three back faces of each box, shades the front faces by a fixed light and paints everything back to front; the contact cones are MuJoCo's friction coefficient 1 (half-angle $45^\circ$), drawn with in3.cone from lib/fig.js. The azimuth and elevation sliders only change the view, so they can move while the simulation runs.

Deck script for a live MuJoCo slide

<script src="lib/fig.js"></script> <script src="lib/models.js"></script>
<script src="lib/mj.js"></script>   <!-- inserts lib/mujoco/*.js itself -->

const F = Fig("#drop", { w: 560, h: 420,
                         xlim: [-0.25, 0.25], ylim: [-0.06, 0.34] });
MJ.player(document.getElementById("box-drop"), {
  sim: MJ.sim(MODELS.box_on_plane),     // Deck.pending waits for it
  fig: F,                               // "loading" and errors go here
  draw: (sim) => { F.clear(); MJ.draw2(F, sim, { contacts: true }); },
  onReset: (sim) => { sim.qvel[0] = 0.3; },   // also runs on [reset]
  controls: "#drop-ctl", speed: 0.25, loop: 1.2,
});
  • The player animates only while its slide is current (present mode) or on screen (read mode), and draws one frame in print mode.
  • sim.contacts() gives each contact's frame, distance and force; fworld is the force of geom1 on geom2 in world coordinates.
This is the whole pattern the three demonstrations use. MJ.sim compiles the MJCF text and returns a promise; MJ.player waits for it, calls onReset once, draws the first frame, and starts when the slide is shown. The step function defaults to sim.advance(dt), which keeps simulation time in step with wall time multiplied by speed. A custom step(dt, sim) can sample every engine step with sim.advance(dt, {each}), as the box-drop strip chart does. Model edits (sim.setOpt, sim.geomParam) take effect at the next step. The full API is in the header of lib/mj.js.

Engine timings measured in this browser

waiting for the first player ...

Times are milliseconds since the page started loading. Compute rate is engine steps per second of time spent inside mj_step; real-time rate is steps per second of wall time while the slide animated. Visit the demonstration slides first to fill the table.

The table reads MJ.stats, which lib/mj.js fills as it loads and runs. Loading has three parts: inserting the two lib/mujoco scripts (the 3.3 MB base64 wasm), decompressing the wasm with DecompressionStream, and starting the module. Each player records when its simulation became ready and when it drew its first frame. For small models the compute rate is a few hundred thousand steps per second, so a slide can afford hundreds of rollouts per second for sampling MPC; the real-time rate is the timestep's 500 steps per second multiplied by the player's speed.
